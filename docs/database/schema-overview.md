# Database schema overview

**Engine:** PostgreSQL 17 (local: Docker `postgres:17-alpine`). **ORM:** Prisma.
**Location:** `packages/db/prisma/schema.prisma` (ADR-018), from Phase 4.
**Status:** Design only (Phase 0). See [`erd.md`](./erd.md) and [`data-dictionary.md`](./data-dictionary.md).

## Conventions

| Topic            | Rule                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Primary keys     | `uuid`, generated by the app as UUIDv7 (time-ordered for index locality), Postgres `uuid` type                                  |
| Naming           | Prisma models in PascalCase, fields in camelCase. Tables keep Prisma defaults (quoted identifiers)                              |
| Timestamps       | `timestamptz(3)` in UTC. `createdAt` default `now()`, `updatedAt` via `@updatedAt`                                              |
| Dates            | `date` for DOB, business dates and expiry dates                                                                                 |
| Money            | `Int` paise (max ≈ ₹2.1 crore per value; `BigInt` for aggregates)                                                               |
| Enums            | Prisma enums for stable vocabularies (status, channel). Lookup tables for clinic-editable lists (appointment types, procedures) |
| Ownership        | `clinicId` on operational tables, `branchId` where location matters (ADR-014)                                                   |
| Soft delete      | Only where justified (see ERD §7). Partial unique indexes ignore deleted rows                                                   |
| Case-insensitive | `citext` for user email                                                                                                         |

## Extensions (enabled in the first migration)

- `btree_gist`: appointment overlap exclusion constraints.
- `pg_trgm`: fuzzy patient search and duplicate detection on name.
- `citext`: case-insensitive email.

## Raw-SQL objects (Prisma cannot model these, so they are kept in migration SQL)

| Object                                                                                                                                          | Purpose                       | Phase |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | ----- |
| `Appointment.timeRange` generated column + 2 exclusion constraints                                                                              | Double-booking prevention     | 5     |
| GIN trigram index on `Patient.fullName`, btree on normalised phone                                                                              | Search / duplicate detection  | 5     |
| Partial unique index on active `ConsentRecord` per (patient, purpose)                                                                           | One current state per purpose | 5     |
| `REVOKE UPDATE, DELETE` on AuditLog, Payment, Refund, ClinicalNoteVersion, ToothConditionHistory, ConsentRecord, StockMovement for the app role | Immutability                  | 4–7   |
| Gapless invoice and receipt numbering via a per-financial-year `sequence` row locked `FOR UPDATE`                                               | Legal numbering               | 7     |

**Guardrail:** CI runs `prisma migrate diff` against a fresh DB and a test that asserts each
raw-SQL object exists (Phase 4+), so a generated migration can never silently drop them.

## Transactions

- **Scheduling:** create or reschedule uses a single transaction with an availability check, the insert, an outbox event and an audit entry. The exclusion constraint is the final guarantee.
- **Billing:** invoice issue, payment and refund use a transaction with `SELECT … FOR UPDATE` on the invoice row to recompute paid and balance amounts.
- **Merge:** one transaction that re-points all child FKs and writes the snapshot.

## Indexing strategy (initial)

FK columns · `(clinicId, startsAt)` on Appointment · `(dentistId, startsAt)` · `(patientId, createdAt)`
on timeline sources · `Patient.patientNumber` unique · normalised phone · `Message(conversationId, createdAt)` ·
`OutboxEvent(publishedAt) WHERE publishedAt IS NULL` partial · `WebhookEvent(provider, externalId)` unique.
